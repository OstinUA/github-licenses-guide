## 许可证简介

### 公共领域奉献

#### [CC0 1.0 Universal](https://creativecommons.org/publicdomain/zero/1.0/) (`CC0-1.0`)
CC0 旨在全球范围内放弃版权及相关权利；如果放弃在法律上无效，则提供后备许可。其文本不放弃专利权或商标权。若希望数据集、媒体、文档或小段代码可被广泛复用且无需署名，CC0 可能适用；若需要明确的专利授权，则可能不合适。

#### [The Unlicense](https://unlicense.org/) (`Unlicense`)
The Unlicense 将公共领域奉献与后备许可结合起来，文本简短且专为软件编写，但没有明确的专利授权。请确认其措辞以及公共领域奉献的法律效果适用于相关司法辖区。

### 宽松型许可证

#### [MIT License](https://opensource.org/license/mit) (`MIT`)
这是一种简洁的宽松型许可证，允许使用、修改、分发、再许可及销售代码。副本或实质性部分必须保留版权声明和许可文本。许可证没有明确的专利授权。

#### [Boost Software License 1.0](https://www.boost.org/LICENSE_1_0.txt) (`BSL-1.0`)
这种宽松型许可证常用于软件库。声明保留要求通常适用于源码副本和衍生作品；仅由机器可执行目标代码构成的分发有例外。具体条件请阅读许可证全文。它没有明确的专利授权。

#### [BSD 2-Clause](https://opensource.org/license/bsd-2-clause) (`BSD-2-Clause`)
允许以源码或二进制形式重新分发和使用软件，无论是否修改。两种形式都必须保留版权声明、条件和免责声明。

#### [BSD 3-Clause](https://opensource.org/license/bsd-3-clause) (`BSD-3-Clause`)
包含 BSD-2-Clause 的条件，并增加禁止背书条款：未经事先许可，不得使用作者或贡献者的姓名为衍生产品背书或进行推广。

#### [Apache License 2.0](https://www.apache.org/licenses/LICENSE-2.0) (`Apache-2.0`)
这是一种包含明确专利授权的宽松型许可证；在特定专利诉讼情形下，专利授权可能终止。它还要求保留规定的声明、标明修改过的文件，并在适用时保留 `NOTICE` 内容。

### 弱 copyleft 许可证

#### [Mozilla Public License 2.0](https://www.mozilla.org/en-US/MPL/2.0/) (`MPL-2.0`)
MPL-2.0 在文件层面适用 copyleft。分发受约束的软件时，MPL 文件（包括对这些文件的修改）的源代码必须依 MPL 提供。较大的作品可以包含依据其他许可证单独许可的文件，但须遵守 MPL 的条件。

#### [Eclipse Public License 2.0](https://www.eclipse.org/legal/epl-2.0/) (`EPL-2.0`)
EPL-2.0 是一种适合商业环境的弱 copyleft 许可证，并含有明确的专利授权。它适用于受约束的贡献和衍生作品；满足 EPL 要求时，较大作品中的其他部分可以采用不同条款。组合代码前，请查看许可证中的定义和分发条件。

#### [GNU Lesser General Public License v2.1](https://www.gnu.org/licenses/old-licenses/lgpl-2.1.html) (`LGPL-2.1-only`)
LGPL-2.1 面向软件库。遵守其条件时，可以在专有应用程序中使用 LGPL 库。对受 LGPL 约束的库所作的修改仍须遵循 LGPL；分发组合作品时，接收者必须能够修改或替换该库，静态链接可能需要额外步骤。

### 强 copyleft 与网络 copyleft

#### [GNU General Public License v2.0](https://www.gnu.org/licenses/old-licenses/gpl-2.0.html) (`GPL-2.0-only`)
分发受 GPL-2.0 约束的作品时，必须提供其源代码和 GPL 赋予的权利。某种程序组合是否属于受约束作品，取决于具体情况和许可证文本；仅仅位于同一代码库中并不能决定这一点。GPL-2.0 没有明确的专利授权，也没有 GPL-3.0 针对某些情形提出的安装信息要求。

#### [GNU General Public License v3.0](https://www.gnu.org/licenses/gpl-3.0.html) (`GPL-3.0-only`)
GPL-3.0 对受约束的作品规定强 copyleft，并包含明确的专利授权。它还涉及某些设备锁定方式，以及妨碍用户行使许可证权利的限制。具体义务以许可证文本为准，不会自动扩展到任何单独使用的其他程序。

#### [GNU Affero General Public License v3.0](https://www.gnu.org/licenses/agpl-3.0.html) (`AGPL-3.0-only`)
AGPL-3.0 基于 GPL-3.0，并增加网络使用条件。如果修改过的受约束程序允许用户通过网络远程交互，就必须向这些用户提供相应的源代码。该要求针对受许可证约束的软件，并非对所有服务或依赖项一概适用。

## 如何选择许可证

- **希望尽可能自由地复用，且条件较少：**可考虑 CC0 或 The Unlicense，但应先确认公共领域奉献的法律效果及专利条款。
- **希望采用简单的宽松条款：**MIT 较为简洁；BSD-2-Clause 和 BSD-3-Clause 明确规定了再分发条件，BSD-3-Clause 还涉及背书与推广。
- **需要明确的专利授权：**可考虑 Apache-2.0；MPL-2.0、EPL-2.0 和 GPL-3.0 也包含专利条款，但 copyleft 范围不同。
- **希望公开对库或受约束文件的修改，同时允许更大的专有作品：**比较 LGPL-2.1、MPL-2.0 和 EPL-2.0，它们的适用边界和义务不同。
- **希望要求分发受约束作品时提供源代码：**查看 GPL-2.0 或 GPL-3.0。对于符合条件的网络使用，查看 AGPL-3.0。
- **不希望仅含机器目标代码的分发附带相关声明：**查看 BSL-1.0 中的具体例外。

以上仅供初步参考，不构成法律建议。请阅读许可证全文，并检查其与其他项目代码的兼容性。
