Під час створення репозиторію або додавання файлу `LICENSE` на GitHub платформа пропонує **13 стандартних шаблонів ліцензій**. Помилковий вибір може наразити вас на патентні позови, дозволити корпораціям закрити ваш код або ж, навпаки, відлякати розробників від використання вашої бібліотеки.

У цьому репозиторії зібрано наочне пояснення кожної з 13 ліцензій GitHub: що вони дають, чим відрізняються та яку саме обрати для вашого проєкту.

## 1. 🕊️ Суспільне надбання (Public Domain)
*Беріть і робіть що завгодно, можете навіть не згадувати моє ім'я.*

### **Creative Commons Zero v1.0 Universal (CC0-1.0)**
* **Що дає:** Повна відмова від авторських прав. Будь-хто може копіювати, змінювати та продавати роботу без згадки автора. Оскільки в Україні та ЄС неможливо повністю відмовитися від особистих немайнових прав автора, CC0 містить резервну безвідкличну ліцензію та зобов'язання автора не подавати до суду.
* **Головна відмінність:** У пункті 4a прямо зазначено, що вона **не передає патентних прав**. Через це її не рекомендують для великого програмного коду.
* **Для чого підходить:** Датасети, бази даних, графіка, ігрові асети, документація та дрібні сніпети коду.

### **The Unlicense**
* **Що дає:** Передача коду в суспільне надбання, створена спеціально для програмістів.
* **Головна відмінність:** Набагато коротша й простіша за CC0, написана зрозумілою розробникам мовою без складних юридичних конструкцій.
* **Для чого підходить:** Невеликі скрипти, утиліти та проєкти, де автор хоче дати іншим абсолютну свободу без вимоги зберігати копірайти.

## 2. 🤝 Дозвільні ліцензії (Permissive)
*Робіть що завгодно (навіть у закритих комерційних продуктах), але збережіть мій копірайт і не судіться зі мною.*

### **MIT License**
* **Що дає:** Найпопулярніша open-source ліцензія у світі. Дозволяє використовувати код у відкритих і закритих продуктах за єдиної умови — збереження тексту ліцензії та копірайту автора.
* **Головна відмінність:** Максимально коротка (менше 200 слів), не містить складних умов щодо патентів.
* **Для чого підходить:** Вебфреймворки, пакети npm/PyPI, інді-проєкти та бібліотеки, яким потрібне максимальне охоплення.

### **Apache License 2.0**
* **Що дає:** Повна свобода комерційного та приватного використання, модифікації та розповсюдження.
* **Головна відмінність:** Містить потужний **патентний захист** (передача патентних прав користувачам + автоматичне скасування ліцензії, якщо користувач подає патентний позов проти проєкту). Вимагає зазначати факт внесення змін у змінених файлах і зберігати файл `NOTICE`.
* **Для чого підходить:** Серйозне ПЗ, корпоративний опенсорс, ШІ-моделі, великі бібліотеки та фреймворки.

### **BSD 2-Clause "Simplified" License**
* **Що дає:** Практично близнюк MIT. Дозволяє будь-яке використання за умови збереження повідомлення про авторські права у вихідному коді та бінарних збірках.
* **Головна відмінність:** Чітко поділена на 2 пункти (1 — для вихідного коду, 2 — для скомпільованих програм).
* **Для чого підходить:** Системне ПЗ, бібліотеки на C/C++, утиліти екосистеми BSD/Unix.

### **BSD 3-Clause "New" or "Revised" License**
* **Що дає:** Усе те саме, що й BSD 2-Clause, плюс додатковий захист репутації автора.
* **Головна відмінність:** Додає **3-й пункт**: забороняє використовувати ім'я автора чи назву компанії для реклами та просування похідних продуктів без письмового дозволу.
* **Для чого підходить:** Наукові розробки, університетські проєкти та корпоративні інструменти.

### **Boost Software License 1.0 (BSL-1.0)**
* **Що дає:** Надзвичайно ліберальна дозвільна ліцензія, створена спільнотою розробників C++.
* **Головна відмінність:** **Не вимагає** зберігати копірайти під час розповсюдження скомпільованих бінарних файлів (`.exe`, `.dll`, мобільних додатків) — згадка автора потрібна лише при передачі вихідного коду.
* **Для чого підходить:** Header-only бібліотеки (C++, Rust) та геймдев-інструменти.

## 3. 🧩 Слабкий копілефт (Weak Copyleft)
*Ви можете вбудувати мою бібліотеку у свій закритий комерційний продукт, але всі зміни в МОЇХ файлах мають залишитися відкритими.*

### **Mozilla Public License 2.0 (MPL-2.0)**
* **Що дає:** Копілефт на рівні окремих файлів. Дозволяє поєднувати код MPL-2.0 із закритими комерційними файлами в одному проєкті.
* **Головна відмінність:** Якщо ви змінюєте файл під MPL-2.0, ви зобов'язані відкрити зміни в цьому файлі, але ваші власні файли поруч залишаються повністю закритими. Містить патентний захист.
* **Для чого підходить:** Бібліотеки та рушії, автори яких хочуть отримувати покращення від спільноти, не відлякуючи бізнес.

### **Eclipse Public License 2.0 (EPL-2.0)**
* **Що дає:** Зручний для бізнесу слабкий копілефт, популярний у світі Java.
* **Головна відмінність:** Дозволяє комерційне ліцензування скомпільованих модулів, містить чіткі патентні гарантії та опцію сумісності з GPL.
* **Для чого підходить:** Корпоративні плагіни, IDE та Java-фреймворки.

### **GNU Lesser General Public License v2.1 (LGPL-2.1)**
* **Що дає:** Копілефт для бібліотек. Закриті програми можуть підключати LGPL-бібліотеку динамічно (`.dll`, `.so`), не відкриваючи свій власний код.
* **Головна відмінність:** Користувач кінцевої програми повинен мати технічну можливість замінити версію LGPL-бібліотеки. Статична компіляція у закритий файл ускладнена.
* **Для чого підходить:** C/C++ бібліотеки, автори яких хочуть захиститися від закритих комерційних форків самої бібліотеки.

## 4. 🛡️ Суворий та мережевий копілефт (Strong Copyleft)
*Свобода обов'язкова: якщо ви розповсюджуєте програму з моїм кодом, УВЕСЬ ваш проєкт має стати відкритим під тією самою ліцензією.*

### **GNU General Public License v2.0 (GPL-2.0)**
* **Що дає:** Класичний «вірусний» копілефт, під яким працює ядро Linux. Будь-який похідний продукт при розповсюдженні має відкрити повний вихідний код під GPL-2.0.
* **Головна відмінність:** Не містить заборони на апаратне блокування модифікацій («Tivoization») та явних патентних пунктів версії 3.0.
* **Для чого підходить:** Проєкти та драйвери, пов'язані з екосистемою ядра Linux.

### **GNU General Public License v3.0 (GPL-3.0)**
* **Що дає:** Сучасний суворий копілефт. Увесь проєкт, що використовує код GPL-3.0, зобов'язаний відкрити свій код під GPL-3.0.
* **Головна відмінність:** Додає явний **патентний захист**, захист від **Tivoization** (виробники заліза зобов'язані дати користувачам можливість запускати модифіковані прошивки) та заборону на DRM-обмеження.
* **Для чого підходить:** Кінцеві програми, десктопний софт та проєкти ідейних прихильників вільного ПЗ.

### **GNU Affero General Public License v3.0 (AGPL-3.0)**
* **Що дає:** Найсуворіша ліцензія на GitHub, яка закриває «хмарну лазівку» звичайної GPL.
* **Головна відмінність:** У звичайній GPL, якщо компанія змінює чужий код і просто запускає його на власному сервері як вебсервіс (SaaS), не роздаючи файли програми, вона може нікому не показувати код. **AGPL-3.0 зобов'язує відкрити повний код навіть тоді, коли користувачі просто взаємодіють із програмою через мережу (браузер чи API).**
* **Для чого підходить:** Серверне ПЗ, бази даних та вебсервіси, які не хочуть, щоб хмарні гіганти безкоштовно продавали їхню працю як SaaS без повернення коду.

## 🎯 TL;DR — Як обрати за 10 секунд

* **Хочу віддати дані чи графіку без жодних умов:** `Creative Commons Zero v1.0 Universal`
* **Хочу найпростішу та найпопулярнішу ліцензію для коду:** `MIT License`
* **Хочу дозвільну ліцензію з бронею від патентних тролів:** `Apache License 2.0`
* **Не хочу, щоб моїм ім'ям рекламували чужі форки:** `BSD 3-Clause`
* **Не хочу змушувати людей тягати мій копірайт у `.exe` файлах:** `Boost Software License 1.0`
* **Хочу, щоб покращення моїх файлів повертали, але дозволяю закритий софт:** `Mozilla Public License 2.0`
* **Хочу, щоб будь-яка програма з моїм кодом була на 100% відкритою:** `GNU GPL v3.0`
* **Хочу, щоб навіть хмарні SaaS-сервіси відкривали зміни в моєму коді:** `GNU AGPL v3.0`
